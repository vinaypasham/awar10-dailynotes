Workflow : A job to automate our process, We define process in a single YAML file. 
File location should be : repo --> .github / workflows / abc.yaml

---

Event : An event is the trigger that starts our workflow.

push 				: When any code changes pushed to repo.
pull request		: When any PR is created
schedule			: Run at specific time intervals using Cron
workflow_dispatch	: Manually trigger by user

---

Job : A job contians multiple steps that runs to perform the required activity.
One job can contains multiple steps.
-> Single workflow can contians multiple jobs. 

1. Identify secrets
2. Verify code quality
3. Send alerts
4. print result

Step : A single task inside a job

---

Runner : THis is a virtual machiene, that executes our jobs. These are microVMs (VM/Contianer)

GitHub Hosted Runner : GH provide these.. (unlimited runs : public repo.. 2000 minutes : for Private repos)
Self Hosted Runner : We can configure our server / ec2 to perform the job. As we providing machiene, we call it as self hosted runner.

---

Github actions: An action is a reusable piece of code that does a specific task. Instead of writing logs/jobs from scratch, we can use preconfigured actions.

actions/checkout@v6				- Checks out our repository code
gitleaks/gitleaks-action@v3		- Checks for secrets leaks


=========

GHA has 3 types of variables

workflow variables: We can define in our YAML file itself					$VAR_NAME
	--> JOB LEVEL, Workflow Level, Step Level
Configuration variables: In github UI, Under settings, we can define		${{ vars.VAR_NAME }}
Context Variables : Prebuild variables provided by GitHub					${{ github.VAR_NAME }}

Trivy : Trivy is an open-source all-in-one vulnerabilities and security scanner. It is highly popular in DevSecOps because it's extremely fast, it's stateless, and easy to integrate with CI/CD pipelines. 

Other tools are generally designed for single-purpose scanning but Trivy can scan for CVEs, common vulnerable dependencies, exposures, and we can even scan IAC infrastructure-as-code misconfigurations as well. 

trivy image nginx:latest (image scan)
trivy fs --scanners vuln,secret,misconfig ./my-project (local-file system scan)
trivy repo https://github.com (git repo scan)
trivy k8s --report summary cluster (k8s cluster scan)

CAST : comprehensive testing : a methodology that combines multiple security tools. We can treat this as a mixed box that looks at our code, looks at the running application, and checks the third-party applications and integrations. 
With CAST we can find coding flaws, runtime errors, and vulnerable open-source libraries. 


SAST : static application security testing : bandit, sonarcloud.
- A single tool that scans uncompiled source code 
- The testing style is white-box testing. It will inspect the entire code structure. With SAST scanning we can find coding practises, hard-coded passwords, and structural errors. 
- SAST comes into the shift-left mechanism. Shift left means we can identify the issue early in the development when the developer is actually writing the code. 

---


WHy Sonarcloud: Sonar Cloud supports 40+ programming languages and frameworks. Sonar Cloud has a feature called Quality Gate. 

Quality Gate: it acts as a go/no-go filter. It stops the code from processing if it fails to meet specific metrics like low code coverage and high bug density. 

Bugs : Its a code error that will cause functional failure.
Vulnerabilities : a security weakness that can put our obligation at risk of exploitation 
Code Smells : poorly structured code that is not actually broken but it makes maintenance difficult over time 
Duplication : Sonar can highlight the duplicated code blocks to prevent redundancy.
